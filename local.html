Three questions, in order: can I run this at all (the hardware floor), what does that cost me, where I am (capex + running cost by region), and what happens after it loads (the operating reality most guides skip). These are planning estimates derived from published architecture specs and community hardware guides — not measured on our own hardware. Verified as of —.

Pick a model

Total params ≠ active params. For MoE models the compute footprint tracks the active count — the headline total misleads if read as hardware demand.

Can I run it?

A hardware floor means "loads and runs" — not "runs fast for a team." See the operating reality below before buying anything.

What does that cost, where I am?

Prices are hand-sourced and dated, not live — see Methods below.

What happens after it loads
  • Serving stack — vLLM/SGLang setup; context length is a memory decision, not a free setting. Kimi K3's 1M-token window realistically starts at 128k–256k locally unless the KV cache is sharded across many GPUs.
  • Concurrency — loading a model isn't serving a team. Tier B fits one user comfortably; tiers D/E are needed before several people can prompt at once without queuing.
  • Storage — weights alone are large (Kimi K3 ≈ 594GB); add checkpoint and quantisation headroom on top.
  • Maintenance — driver/CUDA upgrades, re-quantisation as community GGUF ports mature.
  • Licence — read the repo LICENCE directly. Modified MIT, Apache 2.0, MIT, and Meta's custom terms differ materially at commercial scale.
  • Hybrid pattern — sensitive work local, frontier/long-context bursts via API. Often the correct answer.

How has this changed since 2025?

Flagship-class releases only — not every model a provider shipped. Points only where a real release exists; no interpolation across silent quarters. Capex uses US baseline pricing (the region selector above doesn't affect this chart).

Methods & sources
