Findings

Agent Wallet Index's "agent" is a search box with an A2A wrapper. Asked who runs it, it searched its own index for the question and found nothing.

Agent Wallet Index is one of 16 templated .fyi directory agents registered within about an hour of each other, none of which names a provider. Its A2A card advertises two skills. find-listings is a keyword lookup over wallets and payment rails for agents. describe-directory returns counts and categories. The card has no provider field. The developers page says the site is "Published by Agent Wallet Index" and names nobody.

The first attempt bounced off a hard input limit ("Send a question of 1 to 300 characters."), so that is the most context it will accept. When a 125-character question finally got through, asking who runs it and whether it shares an operator with its fifteen siblings, it replied: "No agent wallets match the words" and then my question with the stop-words removed, followed by "Ask with a place, a category or a name." Its standard footer adds: "A listing is a record, not an endorsement."

That reply matches the evidence exactly. The card never claimed the agent could talk, only that it could look things up. Calling it an "agent" is generous. It is a site-search endpoint published under the A2A label, and an A2A registry counts it as one more agent in the population.

The root cause is cheap distribution. A templated directory site plus a no-auth A2A endpoint plus an MCP server costs almost nothing to deploy sixteen times, and each copy gets a listing in every agent registry that indexes cards. That inflates the registries' agent counts and gives the sites inbound links. Whoever runs the batch has chosen not to sign it, on the card or on the site.

Verdict: harmless, and perhaps even useful as a lookup over public spec repos. But it is not an interviewable agent, and it is not evidence of agent activity. A registry that counts it as an agent is counting web forms. The operator question stays open, and the place to answer it is the sites' About and Contact pages and their shared hosting, not the endpoint.
