Run It Locally

What it takes to run open-weight AI models on your own hardware, and when that beats buying them as a service.

Three questions, in order: what is the minimum hardware a model needs; what does running it cost each month compared with buying the same model as a service; and what does running it involve day to day. Glossary of terms used on this page
GPU (graphics processing unit)
A specialised computer chip, originally designed for rendering images, that is also well suited to the mathematical operations artificial intelligence models require. Running a model locally requires one or more GPUs.
VRAM (video random-access memory)
The memory built into a graphics card. A model's parameters must fit within the combined VRAM of the GPU or GPUs used to run it, or the model cannot be loaded.
Parameter
One of the numerical values that define a model's behaviour. Larger models, with more parameters, are generally more capable but need more memory and computation to run.
Quantisation and "Q4"
A technique that reduces the numerical precision used to store each parameter, in order to reduce the memory required to load and run a model, at a small and generally acceptable cost to output quality. Parameters are ordinarily stored at 16-bit precision; "Q4" denotes 4-bit quantisation, which reduces the memory footprint by roughly a factor of four. Every figure on this page assumes Q4 quantisation.
Mixture-of-Experts (MoE) and active parameters
An architecture in which a model is divided into specialised sub-networks ("experts"), only some of which are used for each word the model produces. All of the experts still have to be held in memory, so the total parameter count sets how much graphics memory (VRAM) is needed. The "active" parameter count is the part doing the work at any moment, so it sets how fast the model runs and how much computation each answer costs. A Mixture-of-Experts model therefore needs the memory of a large model but runs at roughly the speed of a small one.
Capital cost (capex) and operating cost (opex)
Capital cost is the upfront cost of purchasing hardware. Operating cost is the ongoing cost of running it, principally electricity. This page reports both separately, since they behave differently.
API (application programming interface)
The mechanism by which software requests a response from a provider's hosted service over the internet, as an alternative to running a model on local hardware.

Choose a model

Mixture-of-Experts models have different total and active parameter counts: memory needs follow the total, speed follows the active count (see Glossary, above). The Q4 weight size is the storage and graphics memory (VRAM) needed to load the model at 4-bit precision, which this page assumes throughout. That cuts memory needs to about a quarter of the unquantised model's, at a small cost to output quality.

When self-hosting makes sense

Reasons to run it yourself

  • Data must stay on your premises. Regulation, client contracts or data classification rule out sending it to a third party. In financial services this is usually the deciding reason, not cost.
  • Steady, high volume. Hardware only beats per-token prices when it is kept busy, day after day.
  • Latency or offline needs. Responses must be fast and predictable, or work without an internet connection.
  • Fine-tuning. You need to adapt the model's weights to your own data.

Reasons to buy it as a service

  • Spiky or uncertain demand. You pay only for what you use; idle hardware still costs money.
  • You need frontier quality. The most capable models are not released as open weights.
  • No team to run it. Serving software, drivers, security patching and capacity planning are ongoing work, and none of it is in the costs above.
Operational considerations
  • Serving software. Running a model requires dedicated serving software, such as vLLM or SGLang (open-source programs designed to run large language models efficiently). The longest text a model can consider at once (its context length) is limited by memory, not just a software setting: a model's advertised context window is often out of reach on local hardware unless its working data (the "KV cache") is spread across several graphics cards.
  • Concurrent users. The ability to load a model does not imply the ability to serve multiple people simultaneously. Tier B hardware comfortably supports a single user. Supporting several people at once without requests queuing typically requires Tier D or Tier E hardware.
  • Storage requirements. The model weights alone need substantial storage: about 1,390 GB for Kimi K3 at Q4. Allow more for saved copies of the model and for trying other quantisation levels.
  • Ongoing maintenance. Running a model locally requires periodic maintenance, including updates to graphics-card drivers and to CUDA (NVIDIA's software platform for running computations on its GPUs), and occasionally re-processing ("re-quantising") the model as improved community-produced versions become available. GGUF is a common file format used for these community-produced, quantised models.
  • Licensing. The terms under which a model may be used vary by provider and should be read directly from the official source repository. The licences on this page (Apache 2.0, MIT, Meta's Llama licence and custom licences from Kimi, MiniMax and Mistral) differ materially, especially for commercial use at scale.
  • Hybrid deployment. Many organisations run sensitive workloads on local hardware while using a hosted API for occasional tasks that require the largest models or the longest context windows. This hybrid approach is frequently the most practical outcome.

Methods and sources

Sourcing hierarchy: parameter counts, licences and release dates come from each model's Hugging Face card (or the provider's own page), checked November 2026; config.json is used where a card omits the active-parameter count. The number of GPUs is derived by one rule: the Q4 weights plus 20% for working memory, divided by the card's memory. Hosted prices are the median across providers in the LiteLLM registry. National energy statistics are used for electricity prices. The single-user speed on a consumer GPU is its published memory bandwidth (RTX 4090: 1,008 GB/s) divided by the model's active weights. Every model links to its model card or the provider's own model page. Enterprise-tier GPU price and power draw are read from the Cost-of-Service Model's figures rather than sourced a second time.
